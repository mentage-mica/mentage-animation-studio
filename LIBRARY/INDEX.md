# Mentage Animation Studio - Knowledge Library

**Version:** 1.0 | **Last Updated:** May 2026 | **Status:** Active & Maintained

## 📚 What is LIBRARY?

This folder contains all knowledge, assets, guidelines, and reusable resources for the Mentage Animation Studio. It's organized by purpose and built to scale - meaning you can copy this entire folder structure to new projects.

## 🗂️ Folder Structure

```
LIBRARY/
├── 00_BRAND/           Brand identity, guidelines, visual assets
├── 01_STRATEGY/        Strategic context, GTM, business intelligence
├── 02_COMPLIANCE/      Rules, guardrails, legal boundaries  
├── 03_PRODUCTION/      How we make things: templates, prompts, scripts
├── 04_REFERENCE/       Research, source materials, analytics
└── 05_AGENTS/          AI agent files (.skill files)
```

## 🚀 Quick Start

**New to this repo?**
1. Read the folder README that matches your task
2. Each folder has a `README.md` explaining its purpose
3. Links between folders show how they connect

**Want to use this in another project?**
- Copy the entire `LIBRARY/` folder
- Update README files with your project name
- Add/remove folders as needed for your scope

## 📂 Folder Guide

### [00_BRAND](./00_BRAND/README.md)
Design system, color palettes, logo usage, brand voice guidelines. Use this when creating any branded content.

### [01_STRATEGY](./01_STRATEGY/README.md)
Executive context, competitive intelligence, market positioning. Reference before major decisions.

### [02_COMPLIANCE](./02_COMPLIANCE/README.md)
Legal requirements, brand guidelines, content boundaries. Check before publishing.

### [03_PRODUCTION](./03_PRODUCTION/README.md)
Reusable templates, AI prompts, automation scripts. Reference when creating content.

### [04_REFERENCE](./04_REFERENCE/README.md)
Research materials, competitive analysis, analytics data. Use for context and validation.

### [05_AGENTS](./05_AGENTS/README.md)
AI agent definitions and capabilities. Reference when working with AI partners.

## 💡 How to Maintain This

**Adding new content:**
- Keep files in their logical folders
- Update the parent folder's README
- Link to related content using markdown

**Removing content:**
- Delete the file
- Update relevant README files
- Check for broken links

**Version control:**
- All changes are tracked in git
- Use meaningful commit messages
- Link to issues/PRs when making structural changes
